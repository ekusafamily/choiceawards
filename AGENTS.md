# Project Instructions

## General
- Do not use emojis in the application UI.
- Do not add emojis to code comments, commit messages, or generated text.
- Keep the design professional and modern.
- Do not make unnecessary changes to files unrelated to the requested task.
- Before changing existing functionality, understand how it currently works.
- Do not remove existing features unless explicitly instructed.

## Code
- Write clean, readable code.
- Avoid duplicated code.
- Use the existing project architecture and conventions.
- Reuse existing components where possible.
- Do not introduce a new library when the existing dependencies can solve the problem.
- Keep functions reasonably small and focused.
- Use meaningful variable and function names.

## UI
- Use consistent spacing, typography, and component styling.
- Make the interface responsive for both desktop and mobile.
- Do not use excessive animations.
- Ensure loading, empty, and error states are handled.

## Database
- Do not modify the database schema unless explicitly requested.
- Never delete existing data.
- Validate user input.
- Never expose secrets or API keys in frontend code.

## Before finishing
- Check for syntax/type errors.
- Check that the application still builds.
- Check that the requested feature actually works.
- Summarize the files changed and what was changed.
